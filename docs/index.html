Converge at a Glance

A declarative, Kubernetes-style control plane — built for scale and simplicity.

⎈Declarative resource model
  • Declarative, K8s-like resources with schema-validated specs
  • JSON-Schema-typed kinds — a kind's spec, status & config are JSON Schema in its manifest; the core validates every apply against it and publishes it at /docs (OpenAPI). Generate matching Go & TypeScript types from the same schema — one source of truth, no drift
  • Two-axis status — Synced (reconciled the spec) & Ready (healthy now) collapse into one phase: Ready, Degraded, Failed, Reconciling, Orphaned, Quarantined, Deleting
  • Resync / drift engine — re-probes live health out-of-band; a drifted resource flips Ready=False and re-reconciles
  • Versioned specs — the last N spec revisions are kept per resource; roll back to any earlier one
  • Opaque labels with indexed search
🔗Composition & dependencies
  • A resource composes a whole child graph; logic is pluggable — Go, CEL rules, a kro-style CEL resource graph, Starlark, or any external program (logic-as-data, edited live, no redeploy)
  • First-class dependency edges with value flows — an upstream's output (id, ARN, URL) flows into a dependent's spec; the engine gates until it's ready
  • Child readiness rolls up into the root's status — green only when every child is healthy, and it names the one that degraded it
  • Imperative operations / verbs beyond reconcile
🏛Simple, agnostic architecture
  • One binary + Postgres — no etcd, Redis, Kafka, or message broker; SQL & PL/pgSQL first
  • Kind-blind core: the engine knows no provider — a kind is a CRD applied to the DB; handler code lives only in a worker
  • Workers do anything — Terraform, a shell script, a Kubernetes Job, any cloud/API call — behind a language-agnostic Connect contract
  • Autodiscovery + membership-driven auto-sharding, no leader; control & workers colocated or split
🧩Language-free kinds & reactors
  • No Go required — the stdio provider makes any external program (bash, Python, any binary) a worker over a stdin/stdout JSON protocol
  • Composers as data too — a kro-style CEL resource graph or a Starlark program, shipped in a config bundle and edited live, no redeploy
  • Built-in providers: stdio, stdshell, stdterraform, stdcel, stdstarlark
  • Reactors — durable side effects on a transition ("after X, do Y"): an editable subscription wires them; an emergent saga, no saga type
🎛Live operability & lifecycle
  • Web-API-style kind versioning — vpc/v1 → vpc/v2; the broker routes by exact (kind, version), migration is a uuid-stable in-place flip, a version can be retired
  • Per-kind global concurrency caps — throttle a kind cluster-wide (e.g. respect a cloud API rate)
  • Runtime-editable config — change a kind's config or CRD live; workers pick it up with no redeploy
  • Soft-delete + reverse-dependency cascade — finalizers, ordered teardown, orphan-grace pruning, operator quarantine
📊Visibility & resilience
  • Rich embedded UI: topology viewer, dependency graph, cluster/fleet view, resource events
  • Powerful label search; CQRS — UI & read queries target a read replica
  • At-least-once, idempotent — work is redelivered safely; a poison task dead-letters, transient failures retry with backoff
  • Reactive, not polled — work is pushed, so changes propagate immediately
⚡Performance & scale
  • >4,000 reconciliations/sec (provider time excluded)
  • Tuned for 10M+ resources on one Postgres primary
🧪Testability
  • End-to-end testable in parallel, with chaos / HA / replica suites
  • Real resources & policies via AWS LocalStack
  • No mocks — the real Connect binaries and a Postgres testcontainer
